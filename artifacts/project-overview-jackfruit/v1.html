Jackfruit 核心功能

用户打开 App，一边和 AI 语音聊天，一边给自己“孵化”出一个会动、会说话的数字分身。整个 App 目前只有这一段 Onboarding，聊完之后要进入的角色主页还没接上。

一眼看懂

产品形态4 个阶段的沉浸式 Onboardingcharacter-app，手机竖屏，首页 / 就是这个流程
谁来推进每一步都要用户自己点没有后台自动跑的流程，AI 只在用户操作后才响应
谁来调内容运营在 admin-app 改配置台词、配色、音乐、视频都存在数据库里，不用改代码
最大缺口视频是假的，终点是死路见下方“现状”

三类参与者

用户

授权摄像头和麦克风，聊天、拍照、上传照片、给角色起名。

AI 服务

OpenAI Realtime 负责语音对话；Gemini 负责看照片、分析性格和写台词；Flux Pro（FAL）负责出图；Veo 负责出视频。

运营 / 设计

在 admin-app 的 Onboarding Configs 和 Theme Editor 里改 onboarding_configs，用户下次打开就生效。

用户流程

打个餐馆的比方：Stage 1 是进门迎宾，Stage 2 是点菜，Stage 3 是等上菜，Stage 4 是端菜上桌。每个阶段结束时，数据都会写进 onboarding_sessions。

为什么改流程只改数据库

要解决的问题是：文案、视觉和素材需要反复调整，而调整的人不写代码。所以每个阶段的台词、颜色和视频地址都存成 onboarding_configs 里的 JSONB，前端只负责读取和显示。配置读取失败时，前端会用内置的默认配置，流程照样能走完（OnboardingEngine.jsx:95）。

历史遗留：4 个 Stage 在数据库里仍然用旧的 7-step 字段名，Stage 2 对应 step_3_identity_input，Stage 3 对应 step_5_creation，编号是跳着的（OnboardingEngine.jsx:74）。

Characters、Statuses 和 Prompts 是给角色主页准备的。角色主页被注释掉了，所以用户目前看不到这些配置的效果。

判断体验的高光时刻目前是假的

用户在 Stage 3 和 Stage 4 看到的“自己的视频”，其实是所有人都一样的示例视频；点 ENTER WORLD 后也没有页面可去。建议按下面的顺序处理：

  • 接通视频生成：补上 generate-video-veo，或者改成调用现有的 generate-single-video。
  • 给 Stage 4 结束后准备一个能进入的页面：恢复角色主页，或者先放一个完成页。
  • 把 CLAUDE.md 和 README 更新成现在真实的架构。
